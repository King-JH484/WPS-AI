# Anthony AI Windows 干净迁移实施计划

> 执行环境说明：维护端是 Apple Silicon（M 系列）macOS；目标验收端是 Windows。维护端只完成源码、静态检查和跨平台自动测试，所有 Windows 专属行为必须由目标 Windows 电脑上的 Codex 真机验收。

## 任务 1：整理并验证本机既有修复

**范围**

- PDF 历史会话注入与路径/文本读取兜底。
- DOCX Anthony AI 入口。
- provider 设置避免重复持久化。
- proxy 面板关闭检测的高 CPU 修复。

**步骤**

1. 只纳入明确属于上述修复的源码和测试。
2. 保留用户已有未跟踪文件，不加入提交。
3. 运行相关测试和完整 Node 测试。

## 任务 2：统一 Windows 共享 `publish.xml` 修改逻辑

**文件**

- 新增 `plugin/tools/update-wps-publish.ps1`
- 修改 Windows 安装/卸载入口
- 新增静态/夹具测试

**要求**

1. 使用 XML DOM，按 `name` 属性精确增删两品牌条目。
2. 原 XML 无法解析时失败退出。
3. 临时文件解析复验后原子替换。
4. 保留第三方完整节点语义。

## 任务 3：修复 Windows 服务、用户身份和失败传播

**文件**

- 补齐缺失的进程停止脚本或改为现有统一脚本。
- 修改 `post-install-windows.bat`、探活脚本和 Inno 安装器。
- 新增安装完成标记生成/验证。

**要求**

1. 安装器按当前 WPS 用户进行非管理员、按用户安装。
2. 清理/构建/注册/探活任一步失败返回非零。
3. 成功标记包含 SID、提交 SHA、路径、Node 和端口。
4. 手动安装入口复用同一核心安装链。

## 任务 4：修复旧 AppId 与旧目录迁移

**文件**

- 修改 `installer/anthony-ai.iss`
- 新增 Windows 只读盘点/干净迁移脚本

**要求**

1. `UsePreviousAppDir=no`。
2. 固定目标用户 `%LOCALAPPDATA%\Programs\AnthonyAI`。
3. 安装前若旧 AppId/旧目录仍存在则中止。
4. 迁移脚本安全枚举卸载注册表 32/64 位视图、任务、Run、进程、目录和端口。

## 任务 5：提供四宿主旧存储清理模式

**文件**

- 新增最小清理页及脚本。
- 添加只清键名、不记录键值的清理逻辑和测试。

**要求**

1. 清理 `lingxi`/`anthony` 产品键及 PluginStorage 对应键。
2. 不加载聊天/provider 主应用。
3. 不清空整个 WPS WebView 数据目录。
4. Word、Excel、PowerPoint、PDF 分别执行并显示复检结果。

## 任务 6：修复品牌与分发元数据

**范围**

- 安装器仓库 URL、构建脚本乱码和当前品牌元数据。
- 面向本 fork 的安装/交接说明。
- 旧品牌兼容和许可证事实保留。

## 任务 7：Mac 维护端验证

1. Node 语法检查。
2. 相关测试与完整测试。
3. PowerShell 脚本静态检查（若本机有 `pwsh`）。
4. Inno/BAT 引用完整性、编码、CRLF、安装包清单静态检查。
5. 明确记录无法在 Mac 验证的 Windows 项目。

## 任务 8：提交、推送与 Windows Codex 交接

1. 检查 diff，排除用户无关文件和构建产物。
2. 提交并推送 `King-JH484/WPS-AI`。
3. 记录远端提交 SHA。
4. 生成一份可直接交给朋友电脑 Codex 的执行型 MD，包含命令、停止条件、安全边界、真机验收和最终报告模板。

## 完成定义

- GitHub 包含本机修复与 Windows 迁移修复。
- Mac 可执行测试通过，既有无关失败单独记录。
- Windows 专属项目明确标为“待目标机验收”，不得在目标机验收前宣称安装成功。
- 朋友电脑 Codex 可依据交接文档完成清理、克隆、构建、安装、四宿主验证、重启验证和性能观察。
